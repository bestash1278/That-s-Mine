# 12단계 — 통합 검증, 사용성 개선, 문서

SPEC §24, §27, §28을 마무리해줘.

1. SPEC §27의 20개 검증 항목을 하나씩 확인하는 체크리스트를 만들고, 자동 테스트로 가능한 것은 테스트를 작성·실행, 수동 확인이 필요한 것은 확인 절차를 적어줘.
2. 백엔드 ./gradlew.bat build, 프론트 npm run build / lint / test를 실제 실행하고 결과를 docs/TEST_RESULTS.md에 그대로 기록 (실행 못 한 항목은 이유 기재, 성공으로 표시 금지).
3. 반응형(모바일 375px, 태블릿 768px, PC 1280px)과 키보드 접근성을 점검하고 문제를 수정.
4. 사용성 테스트 준비 점검 (docs/USABILITY_TEST_READY.md):
   - 과업 A, B를 실제 브라우저(모바일 375px)에서 진행자가 따라 할 수 있는 단계 스크립트로 작성하고 직접 실행해서 막히는 지점을 기록·수정
   - Kakao 키 없는 상태에서도 두 과업이 끝까지 완료되는지 확인
   - 시연 데이터 초기화 후 같은 초기 상태가 재현되는지 확인
   - 연구계획 §7 기록 양식에 맞춘 빈 기록지 템플릿(참여자 ID P01~P05, 시작·종료 시각, 성공 여부, 도움 여부, 오류) 제공. 실제 결과 칸은 비워둘 것
   - 목표 80%(5명 중 4명)는 설계 목표로만 표기하고 달성 여부를 쓰지 않는다
   - docs/DESIGN_RATIONALE.md 추적표에 최종 구현 화면·파일 경로를 채워 넣는다
5. 문서 작성: README.md(한국어 — 스택, 구조, 기능, 환경변수, MySQL 설정, 실행 명령, Kakao 키 발급·허용 도메인 설정, 테스트 계정), docs/API.md, docs/ERD.md(Mermaid erDiagram).
6. 마지막으로 구현한 기능 / 변경 파일 / 실행 방법 / 실제 테스트 결과 / 미구현 기능 / 사용자가 직접 설정해야 할 항목(DB 비밀번호, JWT 키, Kakao 키 등)을 정리해서 알려줘.
