# 5단계 — 분실물 조회·상세

SPEC §8, §12를 구현해줘.

- 검색 조건을 URL 쿼리스트링으로 관리 → 목록/지도 전환, 상세→목록 복귀 시 조건 유지
- 다중 필터, 정렬 4종, 결과 개수, 서버 페이지네이션, 반응형 그리드
- 적용 중인 필터를 칩으로 보여주고 칩마다 개별 해제 버튼을 둔다. 결과 개수는 "조건에 맞는 습득물 N건"으로 표시
- 결과 없음: 안내 + 조건 초기화 + "분실 신고하기". 분실 신고 이동 시 현재 keyword/categoryId/날짜를 쿼리로 넘겨 폼에 미리 채운다
- 상세 화면 정보 순서(과업 A를 3분 안에 끝낼 수 있게):
  1. 사진, 물품명, 상태 배지, 공개 특징
  2. "발견한 곳" 카드: 발견 날짜·시간, 건물, 상세 위치
  3. "지금 보관 중인 곳" 카드: 보관 부서·장소·상세 위치, 운영 시간, 문의처
     - 보관 미확정이면 "보관 장소 확인 중"
     - TEMPORARY이면 "습득자가 임시 보관 중 · 반환 신청 시 관리 부서가 연결" (연락처 비공개)
  4. "찾아가는 방법": pickup_guide(신분 확인 수단 등)와 "실제 수령 시 담당자가 소유 여부를 확인합니다" 안내
  5. 반환 신청 / 목록으로 버튼(모바일에서는 하단 고정)
- 두 위치 카드는 제목·아이콘·색을 다르게 하고, 모바일에서도 보관 카드가 첫 화면 가까이 보이게 해. 발견 장소와 보관 장소가 같은 건물이면 "발견한 곳과 같은 건물에 보관 중"을 텍스트로 알린다
- RETURNED면 반환 신청 버튼 비활성화(이유 텍스트 표시)
- 지도 마커 영역은 6단계에서 연결할 수 있도록 자리만 마련
