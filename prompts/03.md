# 3단계 — 습득물 조회·등록 API (핵심)

SPEC §20의 습득물 API와 장소/카테고리 API를 구현해줘.

- GET /found-items: keyword(물품명+공개 특징, 동의어 확장 적용), categoryId, buildingId(발견 건물), startDate~endDate, status, sort(4종, 기본 최신 등록순), page/size → 페이지 응답(content, totalElements, totalPages, page)
  - 목록 항목 DTO에 보관 요약을 포함: storageStatusLabel, storageName(미확정이면 null → 프론트는 "보관 장소 확인 중")
  - keyword 검색은 private_features를 절대 대상으로 삼지 않는다(비공개 특징이 검색으로 추측되는 것을 방지)
- 공개 상세 DTO와 관리자·작성자용 DTO를 분리한다. 공개 DTO에는 private_features, 습득자 정보가 필드로 존재하지 않아야 하며, 이를 확인하는 테스트(JSON에 키가 없음)를 작성한다
- 상세 응답에 보관 장소의 contact_phone, operating_hours, pickup_guide를 포함한다(공식 보관 장소 정보이므로 공개)
- GET /found-items/{id}, /recent, /map(minLat~maxLng 범위 + 필터)
- POST /found-items: multipart(JSON 파트 + images ≤3), 미래 날짜/시간 거부, 좌표 범위 검증, 이미지 매직바이트 검증, UUID 파일명, 대표 사진 지정
- custodyType=HANDED_OVER일 때만 보관 위치 필수, 아니면 응답에 "보관 장소 확인 중" 표시용 필드
- 응답 DTO에서 습득자 개인정보 제외
- 공통 예외 응답 형식, 컨트롤러 통합 테스트(MockMvc) 작성 후 실행
- 인증은 다음 단계에서 붙이므로 지금은 SecurityConfig에서 GET만 permitAll로 열어두고 POST는 임시 허용 후 TODO 표시
