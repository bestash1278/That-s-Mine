# 교내 분실물 조회 및 신고 시스템 개발

## 1. 프로젝트 개요

교내에서 발생하는 분실물 및 습득물 정보를 통합적으로 관리하는 반응형 웹 애플리케이션을 개발한다.

기존에는 학생들이 분실물을 찾기 위해 여러 게시판이나 학생 커뮤니티, 교내 관리 부서를 개별적으로 확인해야 하는 불편함이 있다. 이를 개선하기 위해 분실물 조회, 습득물 신고, 분실 신고, 지도 기반 위치 확인 및 등록 기능을 제공하는 시스템을 구현한다.

휴먼컴퓨터인터페이스 수업 프로젝트이므로 기능 구현뿐만 아니라 사용 편의성, 직관적인 인터페이스, 오류 예방, 사용자 경험을 중요하게 고려한다.

## 2. 개발 지침

- 기존 프로젝트 파일과 디렉터리가 있다면 먼저 전체 구조를 분석하고 기존 기능을 유지하면서 개발한다.
- 빈 프로젝트라면 프론트엔드와 백엔드 프로젝트를 각각 생성한다.
- 단순한 화면 예시가 아니라 실제로 실행하고 데이터를 저장할 수 있는 프로그램을 구현한다.
- 모든 화면의 버튼과 입력 요소가 정상적으로 동작하도록 구현한다.
- 프론트엔드와 백엔드의 API 경로 및 데이터 형식을 일치시킨다.
- 사용자에게 표시되는 인터페이스는 한국어를 사용한다.
- 불필요하게 복잡한 기술이나 라이브러리를 사용하지 않는다.
- 개발 완료 후 빌드, 테스트, 오류 검사를 수행하고 해결 가능한 오류는 직접 수정한다.

## 5. 공통 UI 디자인

대학교에서 공식적으로 운영하는 서비스처럼 깔끔하고 신뢰감 있는 디자인을 적용한다.

### 색상

- 메인 색상: #183B62
- 강조 색상: #2563EB
- 기본 배경: #F5F7FA
- 카드 배경: #FFFFFF
- 기본 텍스트: #1F2937
- 보조 텍스트: #6B7280
- 성공: #16A34A
- 오류: #DC2626

### 디자인 규칙

- 불필요한 그라데이션이나 과도한 애니메이션을 사용하지 않는다.
- 카드 형태의 인터페이스를 활용한다.
- 적절한 여백과 명확한 정보 계층을 적용한다.
- 버튼, 입력창, 카드의 디자인을 전체 페이지에서 통일한다.
- 아이콘은 Lucide React를 사용한다.
- 의미 없는 아이콘이나 장식 요소는 최소화한다.
- PC, 태블릿, 모바일 환경에 대응하는 반응형 레이아웃을 구현한다.
- 모바일에서는 터치하기 편한 크기의 버튼을 사용한다.
- 색상뿐만 아니라 텍스트를 통해서도 처리 상태를 구분할 수 있도록 한다.
- 로딩, 오류, 검색 결과 없음, 등록 완료 화면을 각각 구현한다.
- 키보드를 이용한 접근과 입력 요소의 접근성을 고려한다.

## 8. 분실물 조회 페이지

사용자가 잃어버린 물건과 일치하는 습득물을 쉽게 찾을 수 있도록 구현한다.

### 검색 조건

- 물품명
- 물품 특징
- 카테고리
- 발견 장소
- 발견 날짜 범위
- 처리 상태

검색 조건은 여러 개를 동시에 적용할 수 있도록 한다.

### 정렬 기능

- 최신 등록순
- 오래된 등록순
- 최근 발견순
- 오래된 발견순

### 조회 방식

조회 화면에서는 다음 두 가지 방식을 제공한다.

- 목록 보기
- 지도 보기

전환 버튼을 통해 언제든지 조회 방식을 변경할 수 있도록 한다.

조회 방식을 변경하더라도 기존 검색 조건을 유지한다.

### 목록 보기

PC에서는 물품 카드를 여러 열로 배치하고, 모바일에서는 화면 크기에 따라 1열 또는 2열로 배치한다.

각 물품 카드에는 다음 정보를 표시한다.

- 물품 사진
- 물품명
- 카테고리
- 발견 날짜
- 발견 장소
- 보관 상태

검색 결과 개수를 표시하고 서버 기반 페이지네이션을 구현한다.

### 검색 결과가 없는 경우

- 검색 결과가 없다는 안내 문구
- 검색 조건 초기화 버튼
- 분실 신고 페이지 이동 버튼

## 9. 지도 기반 조회 페이지

Kakao Maps JavaScript SDK를 이용하여 캠퍼스 지도 기반 조회 기능을 구현한다.

### 기본 지도 기능

- 초기 지도 중심을 학교 캠퍼스로 설정한다.
- 캠퍼스 중심 좌표와 건물 정보는 설정 또는 데이터베이스에서 관리한다.
- 지도 확대 및 축소 기능을 제공한다.
- 지도 이동 기능을 제공한다.
- 현재 위치 확인 기능을 제공한다.
- 위치 권한이 거부되어도 지도 조회 기능을 이용할 수 있도록 한다.

학교의 정확한 좌표와 건물 정보가 제공되지 않았다면 실제 정보처럼 임의로 확정하지 말고 설정 가능한 구조와 시연용 데이터를 구성한다.

### 물품 마커

습득물의 발견 위치를 지도 위에 마커로 표시한다.

- 빨간색 마커: 습득물 발견 위치
- 파란색 마커: 물품 보관 위치
- 주황색 마커: 분실 신고 위치
- 회색 마커: 반환 완료 물품

지도에 표시되는 위치 유형을 선택할 수 있도록 한다.

동일하거나 가까운 위치에 여러 물품이 등록된 경우 마커 클러스터링을 적용한다.

### 마커 클릭 동작

마커를 클릭하면 다음 정보가 표시되는 팝업 또는 카드가 나타나도록 구현한다.

- 대표 사진
- 물품명
- 발견 날짜
- 발견 장소
- 보관 상태
- 상세 보기 버튼

동일한 위치에 여러 물품이 있다면 해당 위치의 물품 목록을 표시한다.

### 지도 영역 검색

사용자가 지도를 이동하거나 확대·축소한 후 현재 지도 영역의 물품을 조회할 수 있도록 한다.

지도 상단에 '이 지역에서 다시 검색' 버튼을 제공한다.

지도 조회 시에도 물품 종류, 검색어, 날짜, 처리 상태 필터를 적용할 수 있도록 한다.

### PC 레이아웃

- 왼쪽: 검색 조건 및 물품 목록
- 오른쪽: 지도
- 목록에서 물품을 선택하면 해당 위치로 지도 이동
- 지도에서 마커를 선택하면 해당 물품 목록 강조

### 모바일 레이아웃

- 화면 상단: 검색 및 필터
- 화면 중앙: 지도
- 화면 하단: 선택된 물품 정보 또는 접이식 목록

## 10. 습득물 신고 페이지

사용자가 발견한 물건을 빠르게 등록할 수 있는 단일 페이지 입력 폼을 구현한다.

입력 영역을 다음과 같이 구분한다.

### 물품 정보

- 물품 종류: 필수
- 물품명: 필수
- 물품 특징: 선택

물품 종류는 카테고리 버튼을 통해 선택할 수 있도록 한다.

물품 특징 입력창에는 색상, 브랜드, 크기 등을 입력하도록 안내한다.

### 발견 정보

- 발견 날짜: 필수
- 발견 시간: 선택
- 발견 위치: 필수
- 상세 위치: 선택

발견 날짜의 기본값은 사용자의 현재 날짜로 설정한다.

미래의 날짜나 시간을 입력할 수 없도록 검증한다.

### 지도 기반 발견 위치 등록

발견 위치 입력 영역에 지도를 표시하거나 '지도에서 위치 선택' 버튼을 제공한다.

다음 기능을 구현한다.

- 지도 클릭 시 해당 위치에 마커 생성
- 기존에 선택한 위치 변경 가능
- 마커 드래그를 통한 위치 수정
- 선택한 위치의 위도와 경도 저장
- 건물명 검색
- 등록된 교내 건물 선택
- 현재 위치를 기반으로 위치 선택
- 선택된 위치 표시
- 상세 위치 직접 입력

상세 위치에는 층수, 강의실 번호, 출입구 등을 입력할 수 있도록 한다.

지도를 통해 건물을 선택하더라도 실내의 층수와 강의실 번호는 직접 입력할 수 있도록 한다.

지도에서 선택한 좌표는 사용자가 최종 확인한 뒤 신고 양식에 반영한다.

### 사진 등록

- 최대 3장의 사진 업로드
- 장당 최대 5MB
- JPG, PNG, WebP 지원
- 사진 미리보기
- 사진 삭제
- 대표 사진 선택
- 드래그 앤 드롭 업로드
- 모바일 카메라 및 갤러리 연동

확장자뿐만 아니라 실제 이미지 파일 형식과 용량을 서버에서 검증한다.

학생증, 신분증, 카드번호 등 개인정보가 포함된 사진을 공개하지 않도록 안내한다.

### 보관 정보

다음 세 가지 상태 중 하나를 선택한다.

- 관리 부서에 전달 예정
- 관리 부서에 전달 완료
- 습득자가 임시 보관 중

관리 부서에 전달 완료 상태를 선택한 경우 다음 입력 영역을 활성화한다.

- 보관 장소 선택
- 지도 기반 보관 위치 등록
- 보관 장소 상세 설명

발견 위치와 보관 위치는 각각 독립적으로 저장한다.

보관 장소가 확인되지 않은 경우 임의의 장소를 표시하지 않고 보관 장소 확인 중이라고 표시한다.

습득자가 직접 보관 중인 경우 개인 연락처나 개인 거주지를 일반 사용자에게 공개하지 않는다.

### 신고 확인 및 완료

신고 페이지 하단에 다음 버튼을 배치한다.

- 취소
- 신고 내용 확인

신고 내용 확인 버튼을 누르면 입력값 검증을 수행한다.

검증에 성공하면 신고 내용 미리보기 화면을 표시한다.

미리보기 화면에는 물품 정보, 사진, 발견 위치, 보관 위치가 표시되어야 한다.

사용자는 내용을 수정하거나 최종 신고를 등록할 수 있어야 한다.

서버 등록에 성공한 경우에만 신고 완료 화면을 표시한다.

### 입력 항목

- 물품명
- 카테고리
- 물품 특징
- 분실 날짜 또는 추정 기간
- 분실 추정 위치

- 물품 사진

분실 추정 위치는 지도에서 선택할 수 있도록 한다.

분실 위치가 정확하지 않은 경우 여러 장소를 강제로 입력하게 하지 않고 대표 추정 위치와 추가 설명을 입력할 수 있도록 한다.

## 15. 반환 신청 기능

습득물이 자신의 물건이라고 판단한 사용자가 반환을 신청할 수 있도록 한다.

### 입력 항목

- 추가 설명

### 반환 신청 상태

- 신청 대기
- 승인
- 반려
- 반환 완료
- 신청 취소

관리자가 소유 여부를 확인한 후 신청을 승인하거나 반려할 수 있도록 한다.

반환 신청을 승인한 것과 실제 반환이 완료된 것을 구분한다.

동일한 물품이 여러 사용자에게 중복 반환되지 않도록 서버에서 트랜잭션 및 동시성 처리를 적용한다.

## 17. 유사 물품 추천 기능

분실 신고와 습득물 데이터를 비교하여 관련성이 높은 물품을 추천한다.

외부 AI API를 사용하지 않고 규칙 기반 점수 계산 방식으로 구현한다.

초기 유사도 평가 기준은 다음과 같다.

- 카테고리 일치: 30점
- 물품명 및 특징 유사도: 30점
- 위치 근접도: 25점
- 날짜 유사도: 15점

위도와 경도를 이용한 거리 계산에는 Haversine 공식을 사용할 수 있다.

발견 날짜가 분실 추정 기간과 논리적으로 맞지 않는 물품은 추천 대상에서 제외하거나 감점한다.

총점을 기준으로 가능성이 높은 물품을 우선 표시한다.

반환 완료된 습득물은 추천 대상에서 제외한다.

추천 결과는 소유 여부가 확정된 결과가 아니라 유사 물품이라는 점을 명시한다.

## 23. 보안 및 오류 처리

- 비밀번호를 평문으로 저장하지 않는다.
- JWT 유효성을 서버에서 검증한다.
- 작성자 또는 관리자만 신고를 수정하거나 삭제할 수 있도록 한다.
- 관리자 권한을 프론트엔드 표시 여부만으로 판단하지 않는다.
- 데이터베이스 비밀번호, JWT 비밀키, 서버용 API 키는 환경변수로 관리한다.
- 카카오맵 JavaScript 키는 허용 도메인을 설정한다.
- 환경변수 실제 값이 포함된 파일이 GitHub에 업로드되지 않도록 .gitignore를 설정한다.
- .env.example 파일을 제공한다.
- SQL Injection, XSS, 악성 파일 업로드를 방지한다.
- 파일 이름과 저장 경로를 안전하게 처리한다.
- 위도 및 경도가 유효한 범위인지 서버에서 검증한다.
- 발견 위치와 보관 위치를 혼동하지 않도록 한다.
- 중복 신고 제출을 방지한다.
- 서버 오류 발생 시 사용자에게 이해하기 쉬운 오류 메시지를 표시한다.
- API 요청 중 버튼을 비활성화하고 로딩 상태를 표시한다.

카카오맵 API 키가 제공되지 않은 경우 전체 애플리케이션이 실행되지 않는 문제가 발생하지 않도록 한다.

지도 기능을 사용할 수 없는 경우 안내 문구와 건물 선택 및 직접 입력 기능을 대체 수단으로 제공한다.

실제 지도와 시연용 위치 선택 화면을 명확하게 구분한다.

## 24. 사용성 요구사항

휴먼컴퓨터인터페이스 설계 원칙을 적용한다.

### 일관성

전체 페이지에서 버튼, 아이콘, 색상, 입력 방식, 상태 표시 방식을 통일한다.

### 가시성

현재 선택한 메뉴, 검색 조건, 위치, 입력 상태, 처리 결과를 명확하게 표시한다.

### 피드백

검색, 사진 업로드, 위치 선택, 신고 등록, 반환 신청 결과에 대해 즉각적인 피드백을 제공한다.

### 오류 예방

필수 항목 표시, 미래 날짜 제한, 잘못된 파일 형식 제한, 제출 전 미리보기를 구현한다.

### 사용자 제어

신고 취소, 검색 초기화, 위치 변경, 사진 삭제, 입력 내용 수정이 가능하도록 구현한다.

### 인지 부담 감소

한 화면에 불필요하게 많은 정보를 표시하지 않는다.

물품 조회와 신고에서 중요한 정보가 우선적으로 표시되도록 한다.

### 사용성 평가 목표

- 학생 5명 중 4명 이상이 도움 없이 3분 이내에 지정된 습득물과 보관 장소를 확인할 수 있도록 설계한다.
- 학생 5명 중 4명 이상이 도움 없이 주어진 습득물 정보를 정확하게 신고할 수 있도록 설계한다.
- 지도에서 위치를 선택하는 과정이 복잡하지 않도록 한다.
- 입력 오류 발생 시 수정해야 할 항목을 쉽게 확인할 수 있도록 한다.

위 수치는 설계 목표이며 실제 사용자 테스트를 수행하지 않은 상태에서 달성했다고 기록하지 않는다.

- 남색 접이식 우산
- 검은색 학생증 케이스
- 파란색 필통
- 회색 가방
- 스마트폰

각 물품에는 카테고리, 사진 또는 기본 이미지, 발견 날짜, 발견 위치, 보관 위치, 처리 상태를 설정한다.

보관 중, 보관 장소 미확정, 반환 진행 중, 반환 완료 등 여러 상태를 포함한다.

테스트 데이터에는 실제 개인정보를 포함하지 않는다.

테스트용 관리자 및 일반 사용자 계정은 개발 환경에서만 생성하고 운영 환경에서는 자동 생성하지 않는다.

## 26. 개발 순서

다음 순서에 따라 단계적으로 구현한다.

1. 기존 프로젝트 분석 및 개발 환경 구성
2. 데이터베이스 및 Entity 설계
3. 습득물 조회 및 등록 API 구현
4. 공통 UI 및 메인 페이지 구현
5. 분실물 조회 및 상세 페이지 구현
6. 습득물 신고 페이지 및 사진 등록 구현
7. 지도 기반 위치 조회 및 등록 구현
8. 회원가입 및 로그인 구현
9. 분실 신고 및 마이페이지 구현
10. 반환 신청 및 관리자 페이지 구현

12. 프론트엔드와 백엔드 통합 테스트
13. 반응형 UI 및 사용성 개선
14. 오류 수정 및 문서 작성

핵심 기능인 습득물 조회, 상세 정보 확인, 보관 장소 확인, 습득물 신고, 지도 기반 조회 및 위치 등록을 최우선으로 완성한다.

추가 기능을 구현하는 과정에서 핵심 기능의 정상적인 동작이 훼손되지 않도록 한다.

## 29. 최종 작업 지시

단순히 개발 계획이나 예시 코드만 출력하지 말고 실제 프로젝트 파일을 생성하거나 수정한다.

기존 파일이 있다면 먼저 분석하고 불필요한 삭제 또는 전체 구조 변경을 피한다.

개발 중 필요한 의존성을 설치하고 실행 가능한 상태까지 구성한다.

프론트엔드 및 백엔드의 데이터 형식, API 경로, 인증 방식, 상태값이 서로 일치하는지 확인한다.

빌드와 테스트를 실행하고 발생한 오류를 분석하여 가능한 범위에서 수정한다.

API 키나 데이터베이스 접속 정보처럼 사용자에게 받아야 하는 값은 임의로 생성하지 않고 환경변수 예시와 설정 방법을 제공한다.

최종적으로 구현한 기능, 변경한 파일, 실행 방법, 실제 테스트 결과, 미구현 기능 및 추가 설정이 필요한 항목을 정리한다.
