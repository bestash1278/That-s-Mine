## 2. 5W1H 문제 정의

| 질문 | 작성란 |
|---|---|
| Who: 누구의 문제인가? | 주 사용자는 교내에서 물건을 잃어버리거나 습득한 학생이며, 분실물 담당자는 운영 절차를 확인할 협조 대상이다. |
| What: 어떤 과업·문제인가? | 분실자는 일치하는 습득물과 보관 장소를 찾아야 하고 습득자는 발견 정보를 신고해야 한다. 정보가 여러 채널에 흩어지고 물품 특징·보관 정보가 불충분하면 탐색과 신고가 어려워진다는 초기 문제 가정을 검증한다. |
| When: 언제 발생하는가? | 강의실 이동·도서관 이용 뒤 분실을 알아차렸을 때와 습득 직후 |
| Where: 어디서 발생하는가? | 캠퍼스 공용 공간에서 발생하며, 이후 교내 안내 채널과 담당 부서에서 정보를 찾는다. |
| Why: 왜 중요한가? | 물품 특징과 보관 장소를 쉽게 확인해야 탐색과 반복 문의에 드는 수고를 줄일 수 있다. |
| How: 현재 어떻게 대처하는가? | 게시판·채팅·안내데스크를 개별 확인한다는 초기 가정이다. 실제 운영 경로는 1주차에 조사한다. |

|---|---|---|---|
| E01 | 안내 채널 분산 여부와 물품 종류·발견 날짜·장소·보관 장소의 안내 여부를 확인한다. | 1주차 학교 홈페이지·게시판·담당 부서 조사 후 자료명·URL·확인일 기록 | 미확보: 가정과 실제 운영이 다르면 문제 정의를 수정한다. |

## 3. 프로젝트 목표

> `[기간]` 안에 `[대상 사용자]`가 `[과업]`을 수행할 때 `[현재값]`인 `[지표]`를 `[목표값]`으로 개선한다.

최종 목표:

> 2학기 안에 교내 분실물 조회·신고 프로토타입을 제작한다. 학생 5명 테스트에서 4명 이상(80%)이 도움 없이 3분 안에 지정 물품과 보관 장소를 정확히 확인하고, 신고 과업에서도 4명 이상이 도움 없이 제시된 정보를 정확하게 입력해 완료하도록 한다. 현재값은 미측정이다. 목표 달성과 현행 방식 대비 개선 여부는 구분해 보고한다.

| SMART 기준 | 확인 내용 |
|---|---|
| Specific | 분실물 검색·상세·보관 장소 확인과 습득물 신고의 두 과업에 집중한다. |
| Measurable | 조회 성공률과 정확한 신고 완료율을 각각 성공 인원÷5명×100으로 계산한다. 80%는 설계 목표이며 실측값이 아니다. |
| Achievable | 1인이 클릭형 조회·신고 프로토타입과 소규모 테스트를 진행한다. |
| Relevant | 분산된 정보 탐색과 반복 문의라는 초기 문제 가정을 검증한다. |
| Time-bound | 두 과업의 기준값 측정, 평가, 수정·핵심 경로 재확인을 기간내완료한다. |

## 5. 해결 가설과 성공 지표

| 해결 가설 | 지표 | 측정 방법 | 현재값 | 목표값 | 값의 성격 |
|---|---|---|---:|---:|---|
| 필터와 명확한 보관 정보가 있으면 원하는 물품을 찾기 쉬워진다. | 도움 없이 3분 내 물품·보관 장소를 정확히 확인한 비율 | 과업 안내 직후부터 물품과 보관 장소 답변까지 측정하며, 오답·시간 초과·진행자 도움은 실패로 기록한다. | 미측정 | 80% 이상(5명 중 4명) | 현재값: 실측 예정 / 목표값: 제안한 기준 |
| 입력 예시와 필수 표시가 있으면 정확하게 신고하기 쉬워진다. | 도움 없이 정확한 정보로 신고를 완료한 비율 | 제시된 발견 장소·날짜·물품 종류·특징을 빠짐없이 정확히 입력하고 제출 확인까지 도달했는지 판정한다. | 미측정 | 80% 이상(5명 중 4명) | 현재값: 실측 예정 / 목표값: 제안한 기준 |

측정 조건: 확인된 현행 흐름을 가상 자료로 재현하고, 이후 새 시안을 평가한다. 물품 수·정보량·과업 난이도를 맞추되 정답 물품은 바꿔 기억 효과를 줄인다. 기기와 안내 문구를 통일하고 참여자 중복 여부를 기록한다. 신고는 시작부터 제출 확인까지 시간을 기록하며, 5분이 지나면 중단하고 미완료로 처리한다. 사진은 미리 준비한 예시 자료로 선택 동작만 시험한다. 실제 신고는 전송하지 않는다. 성공률은 소규모 탐색 결과로 해석하고, 현행 경로를 재현할 수 없으면 비교 불가 사유와 새 시안의 달성률을 보고한다.

| SMART 목표 점검 | 목표문장의 다섯 기준 충족 여부 비평 | 현재값·목표값의 출처 확인 |
| 범위 축소 | 1인이 6주 안에 가능한 최소 범위 3안 요청 | 교육목표와 핵심 사용자 가치 유지 |
| 위험 사전검토 | 윤리·개인정보·기술·일정 위험 목록화 | 실제 프로젝트에 해당하는 위험만 채택 |

추천 프롬프트:

> 이 제안서를 1인·6주 프로젝트라는 조건에서 검토하라. 근거 없는 수치나 기능을 만들지 말고, 범위 과다·검증 불가능한 목표·윤리 위험을 표로 지적한 뒤 최소 실행 범위 3안을 제시하라.

검토 결과:

| 검토 영역 | 지적 사항 | 반영한 보완 |
|---|---|---|
| 범위 | 사진 업로드·상태 관리가 실제 서비스 구현으로 확대될 수 있음 | 예시 사진 선택과 가상 상태 표시로 한정하고 실제 연동·운영자 시스템을 제외함 |
| 목표 검증 | 현재값 없이 개선을 확정하고 신고의 누락 여부만 평가함 | 목표 달성과 개선 여부를 분리하고 정확한 입력·도움 여부를 판정 기준에 추가함 |
| 윤리·접근성 | 공개 정보로 소유권을 오인하거나 상태를 색상만으로 구분할 위험 | 담당자 확인 안내·정보 가림·색상과 글자 병기·조사 동의 절차를 포함함 |

최소 실행 범위 3안:

| 안 | 최소 범위 | 확인할 사용자 가치 | 적용 조건 |
|---|---|---|---|
| 1안: 조회 집중 | 목록·검색·상세·보관 장소 클릭형 화면, 신고 종이 화면 | 원하는 물품과 인수 장소를 찾을 수 있는가? | 일정 지연 시 7번의 축소 범위로 적용 |
| 2안: 조회·신고 기본형 | 조회 경로와 필수 정보 신고·제출 확인 클릭형 화면 | 조회와 정확한 신고를 도움 없이 완료하는가? | 현재 제안서의 기본 계획이며 사진 선택·상태 표시는 가상 사례로 구성 |
| 3안: 저충실도 검증형 | 조회·신고 모두 종이 화면으로 제작하고 화면 전환을 진행자가 대행 | 정보 구조와 항목 이름을 이해하는가? | 도구 사용이 어려울 때 적용하며 클릭형 시안과의 시간 비교는 제한 |

2안 기준으로 계획을 정리했다. 대안 적용 시 변경 사유와 평가 방식의 차이를 기록한다.
