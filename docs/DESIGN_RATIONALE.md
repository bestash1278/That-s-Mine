# 설계 근거 추적표 (Design Rationale)

**작성 목적**: 연구 문서(Chapter 05~06)의 인사이트와 요구사항을 SPEC의 기능·화면과 연결하고, 근거 없는 기능은 명시

**주의**: 아래 모든 수치(시간, 비율, 참여자 수 등)는 HCI 과제용 가상 시나리오 기반이며 실제 사용자 조사 결과가 아닙니다.

## 1. 연구 근거 — 인사이트(I01~I03) 대응

| 근거 ID | 사용자 문제 | 대응 기능·화면 | SPEC 섹션 | 검증 방법 | 비고 |
|---------|-----------|------------|---------|---------|-----|
| **I01** | 분실물 정보가 여러 경로에 흩어짐. 같은 물건을 찾기 위해 검색을 반복함 | 통합 습득물 조회 화면 + 물품명·분류·장소·날짜 필터 | §8(분실물 조회), §20(API: GET /found-items) | 도움 없이 3분 내 정답 물품 찾기(과업 A) | 가상 P01 관찰: 커뮤니티→홈페이지 반복 검색 |
| **I02** | 물건 이름만으로는 판단 어려움. 사진·발견 위치 필요 | 상세 화면: 사진, 특징, 발견 날짜·위치(지도), 보관 상태 명확히 구분 | §12(분실물 상세), §8(목록 카드: 사진·장소·상태) | 올바른 후보 선택 + 발견 위치 정확히 확인 | 카드: 발견 위치(빨강 MapPin) vs 보관 위치(파랑 Archive) 아이콘으로 구분 |
| **I03** | 검색 결과 없음 → 다음 행동 명확하지 않음. 보관 장소·문의처 별도 탐색 필요 | 결과 없음 화면 → 분실 신고 버튼. 상세 화면: 보관 장소, 운영시간, 문의처, 수령 절차 안내 | §8(검색 결과 없음), §12(보관 위치 §23에서 운영시간·문의처 추가), §11(분실 신고 연결) | 결과 없음 상태에서 분실 신고 완료. 보관 장소 화면에서 문의처·시간 바로 확인 | CLAUDE.md: 습득자 임시 보관은 연락처 미노출, "담당부서 연결" 안내 |

## 2. 사용자 요구사항(우선순위 1~4) 대응

| 우선순위 | 요구사항 | 대응 기능 | SPEC 섹션 | 목표값 (가상) | 비고 |
|---------|--------|---------|---------|----------|-----|
| **1** | 여러 게시판 없이 물품명·분류·장소·날짜로 습득물 조회 | 통합 조회 UI + 필터·검색 | §8(검색 조건), §20(GET /found-items) | 도움 없이 3분 내 조회 완료(5명 중 4명 이상) | 평가 과업 A 근거 |
| **2** | 사진·특징과 지도로 물품 구별 가능 | 상세 화면: 사진, 특징, 발견/보관 위치 지도 표시 | §12(상세 정보), §9(지도 마커: 빨강/파랑 구분) | 유사 물품 중 올바른 선택 + 위치 정확히 확인(5명 중 4명 이상) | 발견·보관 위치 혼동 방지 → CLAUDE.md 원칙 1,2 |
| **3** | 보관 장소·문의·결과 없음 시 분실 신고 연결 | 상세 화면 보관 정보 + 결과 없음→신고 버튼 | §12(보관 위치 안내), §11(분실 신고 연결), 추가: storage_locations 테이블에 contact_phone, operating_hours, pickup_guide | 보관 장소 확인 + 결과 없음 신고 완료(각 80%) | C03 근거: "문의처를 별도로 찾음" 문제 해결 |
| **4** | 습득자: 물품·발견 위치를 지도 또는 직접 입력으로 등록 | 습득물 신고: 지도 위치 선택 + 건물/상세 입력 | §10(습득물 신고), §20(POST /found-items) | 도움 없이 위치 정확히 등록(5명 중 4명 이상) | 평가 과업 B 근거. 실제 습득자 원자료 없음 |

## 3. 평가 과업 A, B 대응

| 과업 | 사용자 목표 | 대응 기능·화면 | SPEC 섹션 | 성공 조건 | 시드 데이터 |
|------|-----------|------------|---------|---------|----------|
| **A: 찾기 (3분)** | 도서관 분실 파란색 파우치 찾기 + 보관 장소 답하기 | 조회→검색→상세→보관 위치 확인 | §8(조회), §12(상세) | 도움 없이 3분 내, 올바른 물품 + 보관 장소 정확히 답함 | 정답: "파란색 파우치"(발견:도서관, 보관:다른건물 관리부서) + 오답 후보(남색 파우치, 파란색 필통, 다른 날짜 파우치-RETURNED) |
| **B: 신고 (5분)** | 학생회관 분실 검은색 우산 신고(날짜·장소·종류·특징 입력 후 제출) | 신고 폼 입력→예시 사진 선택→확인 화면→제출 완료 | §10(신고 페이지), 사진은 예시만 사용 | 도움 없이 5분 내, 필수 정보 정확히 입력 후 제출 완료 화면 도달 | 학생회관(건물), 우산(의류·잡화), 예시 사진 frontend/public/demo-photos/ |

## 4. 명세에만 있는 기능 (근거 미지정)

| 기능 | SPEC 섹션 | 근거 | 설계 근거 문서 여부 |
|------|----------|------|-----------------|
| 유사 물품 추천 | §17 | 사용자 연구 근거 없음 | ❌ |
| 반환 신청·반려·완료 | §15, §20 | 사용자 연구 근거 없음 | ❌ |
| 관리자 페이지 | §16 | 사용자 연구 근거 없음(운영자 조사 미시행) | ❌ |
| 회원가입·로그인 | §13 | 기본 기능이나 평가 과업에 직접 포함 아님 | ❌ |
| 마이페이지 | §14 | 기본 기능이나 평가 과업에 직접 포함 아님 | ❌ |
| 반응형 모바일 UI | §5, §8~§10 | 사용 맥락(공강 10분 스마트폰, Chapter 05 §1) | ✅ |
| 지도 기반 위치 선택 | §9, §10 | 설계 의도이나 사용자가 직접 요구하지 않음; 발견·보관 위치 혼동 방지 원칙(I02, CLAUDE.md 원칙 1,2) | ⚠️ 부분 |

**해석**: 
- 평가 과업 A, B가 핵심이므로 이를 지원하는 기능(조회·신고·보관 장소 안내)을 최우선 완성
- 추천, 반환, 관리자 기능은 범위 외(제안서 §4 제외 범위)
- 지도는 위치 혼동 방지를 위해 발견/보관 위치 구분 시 필수이나, 지도 SDK 없거나 실패 시 건물 선택·직접 입력 대체 UI 필수(SPEC §23, CLAUDE.md)

## 5. 설계 원칙 (CLAUDE.md § 디자인 근거)과 연구 근거 연결

| CLAUDE.md 원칙 | 근거 | 구현 위치 |
|-------------|------|---------|
| **1. 조회 경로 주·지도 보조** | I01(정보 분산), 평가 과업 A | 목록→상세로 끝까지 완료 가능; 지도는 선택사항 |
| **2. 발견·보관 위치 혼동 방지** | I02(위치 정보 중요), C02 근거 | 색상(빨강 vs 파랑) + 아이콘(MapPin vs Archive) + 텍스트 라벨 명확히 |
| **3. 보관 장소 다음 "어떻게 찾아가나"** | I03(보관 후 행동), C03 근거 | 상세 화면: 보관 장소 → 운영시간 → 문의처 → 수령 절차 순서 표시 |
| **4. 물품 구별 정보 앞·소유 정보 숨김** | I02, 보안 규칙 | 공개: 사진·특징·날짜·장소; 비공개: 소유자명·학번·개인 연락처 |
| **5. 검색 실패 → 신고로 이음** | I03(결과 없음), C03 근거 | 결과 없음 화면 → 분실 신고 버튼 + 검색 조건 미리 입력 |
| **6. 동의어 사전** | M05(이어폰↔에어팟), 미구현 대상 | 범위 밖 |
| **7. 목록 카드 정보 위치 고정** | I02(정보 구조), 일관성 | 모든 카드: 물품명 → 발견일·장소 → 보관 상태·장소 순서 고정 |
| **8. 모바일 우선** | 사용 맥락(Chapter 05 §1) | 반응형 UI, 하단 내비게이션 |

## 7. 최종 검증

- ✅ 모든 연구 인사이트(I01~I03)가 SPEC 기능과 연결됨
- ✅ 평가 과업 A, B가 대응하는 기능 명확함
- ✅ 연구 수치는 모두 "가상"으로 표시
- ✅ 근거 없는 기능(추천, 반환, 관리자)은 제외 범위로 명시
- ✅ 보안·접근성·모바일 고려사항 포함

---

**최종 결론**: 평가 과업 A, B를 성공적으로 지원하려면 다음 경로를 최우선 구현해야 함
1. 습득물 조회(필터·검색)
2. 상세 화면(사진·발견/보관 위치 명확히 구분)
3. 보관 장소 안내(운영시간·문의처·수령 절차)
4. 분실 신고(지도 또는 건물 선택 + 직접 입력, 평가 과업 B)

나머지 기능은 위 경로가 완성된 후 순차 추가
