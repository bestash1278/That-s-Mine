## 0. 연구 윤리

조사 목적과 걸리는 시간, 기록할 내용을 먼저 설명하고 참여 동의를 받습니다. 답하기 곤란한 질문은 넘길 수 있고, 원하면 중간에 그만둘 수 있다고 안내합니다. 개인정보와 실제 인터뷰 답변은 공개형 AI에 입력하지 않습니다.

인터뷰와 사전 연습은 아직 진행하지 않았습니다. 테스트에서는 미리 만든 물품 정보와 사진을 사용하고, 실제 학교 게시판에 신고하지는 않습니다.

## 1. 연구 목표와 범위

| 항목 | 작성란 |
|---|---|
| 연구 대상 서비스 | 학교에서 잃어버린 물건을 조회하고, 주운 물건을 신고하는 화면입니다. |
| 알고 싶은 사용자 행동 | 물건을 잃어버리면 가장 먼저 무엇을 하는지 알아보려고 합니다. 사진이나 설명 중 무엇을 보고 자기 물건이라고 판단하는지, 주운 물건은 어떻게 신고하는지도 궁금합니다. |
| 설계 결정에 필요한 이유 | 검색 조건과 신고 항목을 정하기 전에 학생들이 실제로 필요로 하는 정보를 확인하려고 합니다. 여러 게시판이나 안내처를 찾아다니는 불편이 있는지도 함께 살펴봅니다. |
| 이번 연구에서 다루지 않을 것 | 학교 시스템 연동, 주인 자동 확인, 배송, 관리자 전체 기능과 푸시 알림은 제외합니다. 이번에는 학생이 물건을 찾고 신고하는 화면까지만 다룹니다. |

연구 목표 한 문장:

> 학생들이 분실물을 찾고 신고하는 과정을 살펴보고, 어디에서 막히는지 알아내 화면 설계에 반영합니다.

## 2. 연구질문

최근 경험을 바탕으로 질문하고, 답변에 따라 필요한 내용을 더 물어봅니다.

| 번호 | 연구질문 | 결과가 영향을 줄 설계 결정 | 답을 얻을 자료 |
|---:|---|---|---|
| RQ1 | 물건을 잃어버렸을 때 처음 확인하는 곳은 어디이며, 그곳에서 못 찾으면 어떻게 합니까? | 조회 화면의 시작 위치, 목록에 보여줄 정보, 장소·날짜·종류별 검색 조건 | 인터뷰에서 설명한 순서, 테스트 중 이동 경로와 검색 시간 |
| RQ2 | 자기 물건인지 확인할 때 어떤 정보를 살펴보며, 보관된 장소는 어떻게 찾습니까? | 사진과 물품 특징의 배치, 보관 장소와 반환 상태 표시, 인수 안내 | 물건을 고른 이유, 보관 장소에 대한 답변, 헷갈린 부분 |
| RQ3 | 주운 물건을 신고하면서 적기 어렵거나 빠뜨리기 쉬운 내용은 무엇입니까? | 필수 항목, 입력 예시, 사진 선택과 제출 완료 안내 | 입력 순서, 빠뜨리거나 잘못 쓴 내용, 수정 과정과 완료 여부 |

## 3. 참여자 계획

| 항목 | 작성란 |
|---|---|
| 포함 기준 | 최근 6개월 안에 학교에서 물건을 잃어버리거나 주운 경험이 있는 본교 학생을 모집합니다. 만 19세 이상이며 조사 참여에 동의한 사람을 대상으로 합니다. |
| 제외 기준 | 분실·습득 경험이 없거나 참여를 원하지 않는 사람은 제외합니다. 저와 화면 제작에 참여한 사람도 테스트 대상에서 뺍니다. |
| 목표 인원 | 2주차에 학생 5명과 한 명당 30분씩 인터뷰와 테스트를 진행합니다. 5주차에는 새로 만든 화면을 학생 5명에게 보여주고 다시 테스트합니다. 재참여한 학생은 기록에 표시합니다. |
| 모집 방법 | 학과나 교내 커뮤니티에 모집 글을 올립니다. 어떤 조사인지, 누가 참여할 수 있는지, 30분 정도 걸린다는 점과 보상이 없다는 점을 함께 적습니다. |
| 다양성을 확보할 기준 | 잃어버린 경험이 있는 학생과 주운 경험이 있는 학생을 각각 2명 이상 모집하려고 합니다. 두 경험이 겹쳐도 괜찮습니다. 한 학년이나 같은 공간을 이용하는 학생에게만 치우치지 않도록 합니다. |
| 보상 여부 | 별도 보상은 없습니다. 자발적으로 참여하도록 하며, 참여 여부는 성적이나 학교 서비스 이용과 관계없다고 안내합니다. |
| 중도 중단·철회 처리 | 중단을 요청하면 바로 마칩니다. 조사 후 7일까지 참여자 번호를 알려주면 해당 기록을 삭제합니다. 삭제 요청 기간이 지난 뒤 결과를 제출합니다. |

## 4. 방법 조합

| 방법 | 수집할 자료 | 연결 연구질문 | 한계·편향 | 보완 방법 |
|---|---|---|---|---|
| 방법 1: 반구조화 인터뷰 | 최근에 물건을 잃어버리거나 주웠을 때 했던 행동과 그 이유 | RQ1·RQ2·RQ3 | 당시 일이 잘 기억나지 않아 빠뜨리는 내용이 있을 수 있습니다. | 가장 최근 일을 순서대로 물어봅니다. 기억나지 않으면 넘어갑니다. |
| 방법 2: 과업 수행 관찰 | 물건과 보관 장소를 찾는 과정, 신고할 때의 입력 내용, 걸린 시간과 실수 | RQ1·RQ2·RQ3 | 실제로 물건을 잃어버렸을 때만큼 급하지 않아 행동이 다를 수 있습니다. | 모두 같은 기기와 안내로 진행합니다. 먼저 혼자 해 보도록 하고, 선택한 이유는 끝난 뒤 물어봅니다. |

왜 두 방법을 함께 사용하는가?

> 이야기를 들으면 당시 상황을 알 수 있고, 직접 사용하는 모습을 보면 어느 부분에서 막히는지 알 수 있습니다. 그래서 두 방법을 함께 쓰려고 합니다. 설명한 내용과 실제 행동이 다르면 이유를 다시 묻습니다. 조사 인원이 적으므로 결과는 이번 화면을 개선하는 데 참고합니다.

## 5. 30분 진행 절차

| 시간 | 단계 | 연구자의 행동·질문 | 참여자 활동 | 기록할 내용 |
|---:|---|---|---|---|
| 0~3분 | 소개·동의 | 무엇을 조사하는지 설명하고 기록해도 되는지 확인합니다. | 설명을 듣고 참여 여부를 결정합니다. | 참여자 번호, 조사일, 동의 여부 |
| 3~8분 | 배경 질문 | 가장 최근 분실·습득 경험을 묻고, 처음 했던 행동부터 들어봅니다. | 당시 상황과 했던 행동을 설명합니다. | 처음 한 행동, 이용한 경로, 어려웠던 점 |
| 8~20분 | 대표 과업 | 찾기 3분, 신고하기 5분을 주고 진행 모습을 지켜봅니다. 안내와 화면 준비에는 나머지 4분을 사용합니다. | 주어진 물건과 보관 장소를 찾고, 예시 정보로 신고합니다. | 성공 여부, 걸린 시간, 이동 순서, 입력 실수, 도움 요청 |
| 20~27분 | 후속 질문 | 물건을 선택한 이유와 진행 중 멈췄던 부분을 물어봅니다. | 선택한 이유와 헷갈렸던 부분을 설명합니다. | 판단 이유, 어려운 항목, 더 필요했던 정보 |
| 27~30분 | 정리·철회 안내 | 답변을 짧게 정리해 맞게 이해했는지 묻습니다. 기록 삭제 방법과 마감일도 알려줍니다. | 잘못 이해한 부분을 바로잡고 추가 의견을 말합니다. | 정정 사항, 추가 의견, 안내 여부 |

대표 과업과 판정 기준:

- 물건 찾기: “오늘 도서관에서 파란색 파우치를 잃어버렸다고 생각해 주세요. 안내 자료에서 주어진 특징에 맞는 물건을 찾고, 현재 어디에 보관되어 있는지 알려 주세요.” 비슷한 물건과 발견 장소·보관 장소가 다른 사례도 넣습니다. 안내가 끝난 직후부터 시간을 재며, 도움 없이 3분 안에 물건과 보관 장소를 모두 맞히면 성공입니다. 오답, 시간 초과, 도움을 받은 경우는 실패로 기록합니다.
- 신고하기: “학생회관에서 검은색 우산을 주웠다고 생각해 주세요. 카드에 적힌 날짜, 장소, 종류, 특징을 보고 신고해 주세요.” 도움 없이 필수 내용을 정확하게 입력하고 제출 완료 화면까지 도달하면 성공입니다. 시작부터 완료까지 시간을 재고 5분이 지나면 미완료로 처리합니다. 사진은 준비한 예시만 사용합니다.
- 2주차에는 학교의 현재 이용 방식을 확인한 뒤 가상 자료로 재현하고, 5주차에는 새 화면을 테스트합니다. 물품 수, 정보량, 난이도, 기기와 안내는 비슷하게 맞추되 정답 물건은 바꿉니다. 현재 방식을 재현하기 어렵다면 비교하지 못한 이유를 적습니다.
- 새 화면의 목표는 두 과업에서 각각 5명 중 4명 이상이 성공하는 것입니다. 현재 성공률은 아직 측정하지 않았습니다. 도움을 받아 완료한 경우는 별도로 적습니다. 물건을 찾았더라도 실제 수령 전에는 담당자의 확인이 필요하다는 점을 안내합니다.

## 6. 질문 가이드

| 구분 | 질문 | 유도 가능성 점검·수정 |
|---|---|---|
| 경험 | 최근에 학교에서 물건을 잃어버리거나 주운 적이 있다고 했는데, 그때 이야기를 해 주실 수 있나요? | “많이 불편했죠?”처럼 답을 정해 놓고 묻지 않습니다. 참여자의 경험에 맞춰 질문합니다. |
| 행동 | 그때 가장 먼저 무엇을 했나요? 그다음에는요? | 게시판이나 안내데스크 같은 답을 먼저 제시하지 않습니다. |
| 맥락 | 그때 어디에서 정보를 찾아봤나요? 바로 찾아볼 여유가 있었나요? | 한 번에 하나씩 묻고 자세한 개인 동선까지 요구하지 않습니다. |
| 장벽 | 하다가 헷갈리거나 어떻게 해야 할지 몰랐던 부분이 있었나요? | 어려운 점이 없었다는 답도 그대로 받아들입니다. |
| 복구·우회 | 원하는 정보를 못 찾거나 신고를 끝내지 못한 적이 있다면, 그다음에는 어떻게 했나요? | 그런 경험이 있는지 먼저 확인하고 해결 방법을 대신 말해 주지 않습니다. |
| 마무리 | 제가 정리한 내용 중 다른 부분이 있나요? 빠진 이야기가 있으면 말씀해 주세요. | 좋았다는 답이나 새로운 기능 제안을 꼭 해야 하는 것처럼 묻지 않습니다. |

## 7. 기록 양식

아래 표에는 직접 본 행동과 들은 말을 적습니다. 행동의 이유에 대한 제 생각은 별도 칸에 적고, 필요한 경우 참여자에게 확인합니다. 기록지에는 참여자 번호(P01~P05), 조사일, 사용한 화면과 기기, 재참여 여부를 표시합니다. 찾기와 신고하기 각각의 시작·종료 시각, 소요 시간, 성공 여부, 도움 여부도 남깁니다.

아래 표는 조사 때 사용할 양식이며, 아직 실제 기록은 없습니다.

| 시간 | 관찰 사실 | 사용자 발화 | 연구자 해석 | 확인 질문 |
|---|---|---|---|---|
| 조회 중 실제 시간 기록 | 어떤 화면을 보고 어떤 검색 조건을 골랐는지 기록 | 실제로 한 말을 기록하고, 요약했다면 표시 | 왜 그렇게 했는지 생각한 내용을 따로 기록 | 그때 어떤 정보를 찾고 있었나요? |
| 상세 확인 중 실제 시간 기록 | 고른 물건과 답한 보관 장소를 기록 | 실제 답변 기록 | 물건을 고른 이유를 답변과 비교 | 어떤 점을 보고 이 물건이라고 생각했나요? |
| 신고 중 실제 시간 기록 | 빠뜨린 항목, 잘못 입력하거나 고친 내용, 완료 여부 기록 | 실제 답변 기록 | 어떤 표현에서 헷갈렸는지 정리 | 이 칸에는 무엇을 적어야 한다고 생각했나요? |

## 8. 윤리·개인정보·위험

| 점검 항목 | 계획 |
|---|---|
| 설명·동의 방법 | 조사 안내문을 함께 읽고 질문을 받은 뒤 동의를 확인합니다. 참여자 번호와 동의한 날짜·시간을 적습니다. 학교에서 정한 동의 절차가 있으면 따릅니다. |
| 최소 수집 개인정보 | 분실·습득 경험과 학년, 주로 이용하는 교내 공간, 기존 안내를 이용해 본 적이 있는지만 확인합니다. 이름이나 학번은 받지 않고, 일정 조율용 연락처는 기록지와 분리합니다. |
| 촬영·녹음 여부와 동의 | 메모와 시간 측정을 기본으로 합니다. 녹음이 필요할 때는 따로 허락을 구하고, 원하지 않으면 녹음하지 않습니다. |
| 익명화 방법 | 이름 대신 참여자 번호로 기록합니다. 답변에 개인정보가 섞여 있으면 빼고 적습니다. 개인 메시지나 사진을 확인하지 않습니다. |
| 파일 보관 위치·접근자 | 자료는 제 PC의 암호화된 폴더에 보관하고 저만 열어봅니다. 동의 기록과 연락처는 따로 두고, 과제에는 개인정보를 지운 요약과 결과만 넣습니다. |
| 삭제 시점 | 조사 7일 후에는 연락처와 참여자 번호 연결표를 지웁니다. 메모와 녹음 파일은 최종 과제 제출 후 30일 안에 삭제합니다. 그전에 철회를 요청하면 해당 자료를 바로 지웁니다. |
| 불편·위험 발생 시 대응 | 참여자가 불편해하면 질문을 넘기거나 조사를 중단합니다. 화면에 개인정보가 나오면 잠시 멈추고 예시 자료로 바꿉니다. 실수로 적은 개인정보는 지웁니다. |

## 9. 5분 파일럿

조사 전에 친구나 가족 한 명에게 질문 세 개를 해 보려고 합니다. 참여할 사람이 없으면 혼자 읽으면서 연습합니다. 이때 나온 답변은 본 조사 결과에 넣지 않습니다.

안내 1분, 질문 3분, 점검 1분으로 나누어 진행합니다. 질문이 길거나 이해하기 어려운 부분이 있는지 확인할 예정입니다. 아래는 점검할 내용과 수정 예시이며, 연습이 끝나면 실제 결과로 바꿉니다.

| 발견한 문제 | 근거 | 수정 전 | 수정 후 |
|---|---|---|---|
| 확인 예정: 발견한 곳과 보관된 곳을 헷갈리는지 | 연습 후 답변 기록 예정 | “물건이 있는 장소를 알려 주세요.” | 수정 예시: “이 물건은 지금 어디에 보관되어 있나요?” |
| 확인 예정: 질문 범위가 넓어서 답변이 길어지는지 | 연습 후 답변 시간 기록 예정 | “분실물과 관련된 경험을 모두 이야기해 주세요.” | 수정 예시: “가장 최근 경험에서 처음 무엇을 했는지 말씀해 주세요.” |

## 10. 제출 전 점검

- [x] 연구질문 세 개가 설계 결정과 연결된다.
- [x] 참여자 포함·제외 기준이 있다.
- [x] 두 방법의 역할과 한계를 구분했다.
- [x] 30분 절차와 기록 양식을 완성했다. (실제 기록은 조사 후 작성)
- [x] 동의·익명화·보관·삭제 계획이 있다.
- [ ] 파일럿 결과를 반영해 질문을 수정했다. (사전 연습 후 확인)

## 생성형 AI 활용 실습

기존 계획을 다듬을 때는 질문이 어색하지 않은지, 같은 설명이 반복되는지 AI로 점검합니다. 제안받은 문장이 조사 의도와 맞는지 확인하고 필요한 부분을 반영합니다.

| 활용 | 추천 방법 | 사람이 확인할 내용 |
|---|---|---|
| 인터뷰 질문 수정 | 작성된 질문에서 어렵거나 답을 유도하는 표현 찾기 | 원래 묻고 싶었던 내용이 유지되는지 확인 |
| 절차 리허설 | 질문 수와 진행 순서를 보고 시간이 부족한 부분 점검 | 직접 연습하면서 실제 소요 시간 확인 |
| 윤리 점검 | 동의 안내나 개인정보 처리 계획에서 빠진 부분 확인 | 학교 기준과 실제 진행 방법에 맞는지 확인 |



AI가 만든 답변을 실제 참여자의 말이나 조사 결과로 사용하지 않습니다.

## 11. AI 사용 기록

| 도구 | 사용 목적 | 입력에서 제거한 정보 | AI 제안 중 거부한 내용 | 사람이 확인·수정한 내용 |
|---|---|---|---|---|
| ChatGPT | 내용에 오류나 어색한부분이 있는지 검토 | 실제 참여자의 답변과 연락처는 입력하지 않았습니다. | 오류부분을 직접수정하지않고 수정방향을 제시하도록하였습니다. | 작성중 오류있는 부분을 확인후 ai의 도움을 받아 내용을 수정하였습니다. |
