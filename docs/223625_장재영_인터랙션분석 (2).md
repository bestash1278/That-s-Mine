## 2. 사용 맥락과 설계 가정



### 2-1. 사용 맥락


| 관찰 항목         | 기록                                                           |
| ------------- | ------------------------------------------------------------ |
| 사용자의 신체·인지 특성 | 키오스크 예매 경험이 적고 열차 종류, 좌석 등급, 운임 조건 등의 용어에 익숙하지 않을 수 있음       |
| 환경 조건         | 안내 방송과 이동하는 승객으로 주변이 혼잡하며, 뒤에 다른 이용자가 대기할 수 있음               |
| 시간·심리 조건      | 열차 출발 시간이 가까우면 빠르게 예매해야 한다는 압박을 느낌                           |
| 사용 기기·입력 방식   | 대형 터치스크린, 화면 키패드, 카드 결제 단말기, 승차권 출력구                         |
| 실패했을 때의 결과    | 원하는 열차를 놓치거나 잘못된 시간·좌석의 승차권을 구매하고, 취소·재예매 또는 직원 도움을 요청할 수 있음 |




### 2-2. 현재 설계가 전제하는 사용자

> 현재 설계는 사용자가 출발역과 도착역을 정확히 알고 있고, 열차 목록에 표시되는 출발 시각·도착 시각·소요 시간·좌석 등급을 빠르게 비교할 수 있다고 가정한다. 또한 좌석 배치도에서 진행 방향과 좌석 번호의 의미를 이해하고, 선택한 열차와 좌석 정보를 결제 전에 스스로 다시 확인할 수 있다고 전제한다.

## 3. 인터랙션 루프


| 단계  | 사용자 목표          | 사용자 행동                                         | 시스템 반응·상태                          | 사용자가 받는 피드백                 | 문제·불확실성                                                  |
| --- | --------------- | ---------------------------------------------- | ---------------------------------- | --------------------------- | -------------------------------------------------------- |
| 1   | 승차권 예매 시작하기     | 시작 화면에서 `승차권 구매`를 누름                           | 승차권 예매 절차를 시작하고 출발·도착역 선택 화면으로 전환됨 | 선택 버튼이 강조되고 역 선택 안내가 표시됨    | 예매·조회·변경 메뉴가 비슷하게 보이면 처음 사용하는 사용자가 망설일 수 있음              |
| 2   | 출발역과 도착역 정하기    | 출발역과 도착역을 검색하여 선택함                             | 선택한 역 정보를 저장하고 날짜·시간 선택 화면으로 이동함   | 선택한 역 이름과 이동 방향이 화면에 표시됨    | 비슷한 역 이름이나 지역명이 있으면 잘못 선택할 가능성이 있음                       |
| 3   | 출발 날짜와 시간 정하기   | 탑승 날짜와 원하는 시간대를 선택함                            | 조건에 맞는 열차를 조회함                     | 조회 중 표시 후 이용 가능한 열차 목록이 나타남 | 시간대 선택 기준이 불명확하면 원하는 범위보다 많은 열차가 표시될 수 있음                |
| 4   | 탈 열차 선택하기       | 열차 목록의 출발 시각, 도착 시각, 운임 등을 비교하고 한 열차의 `선택`을 누름 | 선택한 열차 정보를 저장하고 좌석 선택 단계로 이동함      | 선택한 열차의 정보가 상단에 표시됨         | 여러 정보의 시각적 우선순위가 비슷해 열차를 비교하기 어렵고, 사용자가 이전 화면으로 돌아가 재확인함 |
| 5   | 원하는 좌석 선택하기     | 일반실을 선택하고 좌석 배치도에서 빈 좌석을 누름                    | 해당 좌석을 임시 선택 상태로 저장함               | 선택 좌석의 색이 변하고 좌석 번호가 표시됨    | 열차 진행 방향과 좌석 방향의 관계가 명확하지 않으면 원하는 방향의 좌석인지 판단하기 어려움      |
| 6   | 예매 정보 확인하고 결제하기 | 열차 시각·좌석·금액을 확인한 뒤 카드로 결제함                     | 카드 승인을 요청하고 결제 정보를 처리함             | 결제 진행 안내와 승인 완료 메시지가 표시됨    | 최종 확인 화면에서 중요한 정보가 분산되어 있으면 잘못 선택한 내용을 놓칠 수 있음           |
| 7   | 승차권 받기          | 출력된 승차권을 가져감                                   | 예매를 완료하고 초기 화면으로 돌아갈 준비를 함         | 발권 완료 메시지와 승차권 출력 안내가 표시됨   | 승차권 출력 위치나 발권 완료 여부를 놓치면 기기 앞에서 머무를 수 있음                 |




### 루프 단절 지점

- 가장 크게 멈추거나 망설일 가능성이 있는 단계: `4단계`
- 이유:

> 사용자는 원하는 목적지와 시간대까지 입력했지만, 조회 결과에서 여러 열차의 출발 시각·도착 시각·소요 시간·운임·좌석 상태를 동시에 비교해야 한다. 핵심 정보의 시각적 우선순위가 명확하지 않으면 어떤 열차가 자신의 조건에 가장 적합한지 빠르게 판단하기 어렵고, 선택 후에도 확신하지 못해 이전 화면으로 돌아가 다른 열차를 다시 확인할 수 있다.

## 4. 인터랙션 원칙으로 문제 진단


| 원칙                                | 확인 결과                                                | 해당  | 화면·행동 근거                                   |
| --------------------------------- | ---------------------------------------------------- | --- | ------------------------------------------ |
| 가시성(Visibility)                   | 열차별 출발 시각과 좌석 상태 등 중요한 정보가 다른 정보와 비슷한 크기·강도로 표시됨     | ✓   | 사용자가 한 행만 보지 않고 여러 항목을 반복해서 확인함            |
| 행동 유도성·기표(Affordance & Signifier) | 각 열차의 `선택` 버튼은 조작 가능함을 보여 주지만 선택 기준 자체는 충분히 안내하지 않음  | ✓   | 사용자가 열차를 선택한 뒤 다시 이전 화면으로 돌아감              |
| 피드백(Feedback)                     | 열차 선택 후 선택 결과는 표시되지만 이전 목록과 비교할 정보는 제한적임             | ✓   | 사용자가 선택 결과만으로 확신하지 못하고 목록을 다시 확인함          |
| 대응 관계(Mapping)                    | 좌석 배치도의 좌석 방향과 실제 열차 진행 방향의 관계가 직관적이지 않을 수 있음        | ✓   | 사용자가 좌석 선택 화면에서 진행 방향 표시와 좌석을 번갈아 확인함      |
| 제한 사항(Constraints)                | 잘못된 시간의 열차나 원하지 않는 방향의 좌석을 선택하는 행동을 사전에 충분히 예방하지 못함  | ✓   | 결제 직전까지 사용자가 선택 오류를 스스로 발견해야 함             |
| 접근성(Accessibility)                | 정보가 한 화면에 밀집되어 있으면 작은 글씨를 읽기 어렵거나 인지 부담이 큰 사용자에게 불리함 | ✓   | 여러 열차 정보를 비교하는 과정에서 화면을 가까이 보거나 확인 시간이 길어짐 |

## 5. 핵심 문제 진술

> 열차 예매 키오스크 사용 경험이 적은 승객은 출발 시간이 가까운 상황에서 자신의 일정에 맞는 열차를 선택하려 하지만, 조회 결과에 출발 시각·도착 시각·소요 시간·운임·좌석 상태가 비슷한 시각적 비중으로 제시되어 핵심 정보를 빠르게 비교하기 어렵기 때문에 열차를 선택한 뒤 이전 화면으로 돌아가 다른 열차를 반복해서 확인한다.



### 근거 수준

- ☑ 수업용 가상 화면·행동 시나리오에서 확인한 내용
- ☐ 실제 기차역에서 직접 관찰한 사실
- ☑ 실제 발생 빈도와 영향 정도는 아직 검증하지 않은 추정

추가로 확인해야 할 정보:

> 키오스크 예매 경험이 적은 사용자 8~10명을 관찰하여 열차 목록이 나타난 시점부터 최종 열차를 선택할 때까지 걸린 시간, 열차 행을 비교한 횟수, 선택 후 이전 화면으로 돌아간 횟수, 잘못 선택한 열차의 수, 직원 도움 요청 여부를 측정한다. 사용자가 열차를 선택할 때 가장 중요하게 보는 정보가 출발 시각, 소요 시간, 운임 중 무엇인지도 인터뷰로 확인한다.

### 검증 가능한 가설

> 만약 열차 목록에서 출발 시각을 중심으로 핵심 정보를 일관된 위치에 정렬하고 선택한 열차 정보를 다음 단계에서도 지속적으로 보여 주면, 키오스크 예매 경험이 적은 사용자의 열차 선택 단계 평균 완료 시간이 기존 가상 기준 70초에서 45초 이하로 감소할 것이다.

## 8. 개인 성찰



### 8-1. 처음에는 문제라고 생각했지만 근거가 부족했던 판단

> 처음에는 `키오스크에 정보가 많아서 사용하기 어렵다`고 생각했다. 그러나 이는 너무 포괄적인 판단이며, 가상 관찰에서 확인한 문제는 정보의 양 자체보다 여러 열차의 출발 시각·소요 시간·운임 등 선택에 필요한 정보의 시각적 우선순위가 약하고 비교 구조가 명확하지 않다는 점이었다.



### 8-2. 단순화 과정에서 소외될 수 있는 사용자

> 출발 시각을 가장 크게 강조하는 방식은 운임이 가장 중요한 사용자나 환승·도착 시간을 우선하는 사용자에게는 충분하지 않을 수 있다. 저시력 사용자, 한국어에 익숙하지 않은 외국인 사용자도 고려하여 글자 크기 조절, 다국어, 명확한 아이콘과 같은 대안이 필요하다.



### 8-3. 화면 개선만으로 해결되지 않는 문제

> 열차 지연, 실시간 잔여 좌석 정보의 갱신 오류, 카드 결제 단말기 고장, 승차권 출력 오류, 복잡한 운임·환불 정책은 화면 디자인만으로 해결할 수 없다. 예약 시스템의 데이터 정확성과 역 운영 절차, 직원 지원 체계도 함께 점검해야 한다.



### 8-4. 다음 평가에서 가장 먼저 확인할 내용

> 사용자가 열차 목록에서 실제로 어떤 정보를 우선해서 비교하는지 확인한다. 선택 시간이 오래 걸린 경우 정보의 위치를 찾지 못한 것인지, 열차 종류나 운임의 의미를 이해하지 못한 것인지, 자신의 선택 기준 자체가 명확하지 않았던 것인지 구분하여 기록한다.
